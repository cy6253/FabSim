코어는 됐고, 그 주변이 비어 있다

1 · 재질과 공정은 데이터다

지금 상태

재질은 정수 ID이고, 노브 표("식각액의 선택비 테이블", "슬러리", "종별 D₀·Eₐ")는 각 노드 설명에 흩어져 언급만 돼 있습니다. 기존 Unity에는 EtchantConfig·CmpRateConfig·MaterialColorRegistry가 인스펙터 자산으로 있었는데, 웹판에는 이에 해당하는 계층이 없습니다.

제안 — 세 개의 표

  • 재질 라이브러리 — 이름, 색, 종류(단결정·다결정·비정질·금속·레지스트), 산화 가능 여부, 실리사이드 가능 여부, 도펀트 확산 상수(종별 D₀·Eₐ), 분리 계수. 기본 세트: Si · poly-Si · SiO₂ · Si₃N₄ · Al · Cu · W · TiN · PR · Exposed PR.
  • 공정 라이브러리 — 식각액(HF · BOE · KOH · SF₆ 플라즈마 · Cl₂ · O₂ 애싱)마다 재질별 선택비와 기본 이방성, 슬러리마다 재질별 제거율, 증착 공정(LPCVD · PECVD · PVD · ALD)마다 기본 스텝 커버리지. 노브의 기본값이 여기서 온다 — 학생이 "PVD"를 고르면 커버리지 40%가 자동으로 잡히고, 슬라이더로 바꿔볼 수 있습니다.
  • 물리 상수 표 — Deal-Grove B·B/A(T, dry/wet), 이온 주입 Rp·ΔRp(종, 에너지, 재질). 방정식이 아니라 대입용 데이터입니다(결정 U).

세 표 모두 JSON이고 프로젝트에 포함됩니다. 사용자가 재질을 추가할 수 있게 하면 표가 편집 가능해야 합니다 — 샌드박스라면 허용하는 쪽이 맞아 보이지만 결정이 필요합니다.

2 · 프로젝트와 레시피

프로젝트가 담는 것

  • 격자 설정(크기, 1 복셀 = X nm) · 단위 설정
  • 재질·공정 라이브러리(기본 + 사용자 추가분)
  • 마스크 자산들(2D 비트맵, 이름, 원점)
  • 공정 그래프(노드 · 파라미터 · 연결 · 분기)
  • 스냅샷 캐시(재계산 가능하므로 저장은 선택)
  • 시뮬레이터 버전 — 같은 레시피가 나중에도 같은 결과를 내야 합니다

파일 형식과 공유

프로젝트 하나 = JSON 하나(마스크는 PNG를 base64로 내장). 브라우저 다운로드/업로드로 저장·불러오기. 교사가 레시피를 만들어 학생에게 링크나 파일로 배포하는 것이 교육 도구의 기본 사용 흐름이고, 백엔드 없이도 파일 하나로 됩니다. URL 공유(해시에 압축 인코딩)는 작은 레시피에 한해 가능합니다.

예제 레시피가 곧 커리큘럼

샌드박스라도 빈 화면에서 시작하는 학생은 없습니다. 예제 레시피 세트가 사실상 교육 내용을 정의합니다. 후보: 단일 트렌치와 증착(스텝 커버리지 실습) · LOCOS 소자분리 · STI · 게이트 형성 · 자기정렬 소스/드레인 · 콘택 식각과 텅스텐 플러그 · 다마신 배선 · 완성형 NMOS · CMOS 인버터. 어디까지 만들지는 교육 범위 결정입니다.

3 · 교육 계층 — 가장 비어 있고 가장 값진 곳

지금까지 설계는 "정확한 구조를 만든다"에 집중했습니다. 그런데 교육 도구의 가치는 학생이 무슨 일이 일어났는지 이해하는 데서 나옵니다. 코어가 이미 계산하는 것들을 그대로 학생에게 보여주기만 해도 큰 차이가 납니다.

진단 — 시뮬레이터가 스스로 알아채는 것

보이드 형성, 마스크 정렬 오차로 인한 단락/단선, etch stop에서 멈춤, 마스크 소모로 인한 패턴 손실, 핀치오프 — 코어는 이걸 이미 계산합니다(연결성 검사가 그 부품입니다). 단계별로 "이 단계에서 보이드가 생겼습니다 — 스텝 커버리지가 35%였고 종횡비가 3.3이었습니다" 같은 진단을 붙이는 것은 거의 공짜이고, 교육 효과는 3D 렌더링보다 큽니다.

측정 도구

  • 지점 프로브 — 클릭한 위치의 레이어 스택과 두께
  • 단면 자 — 두 점 사이 거리(nm)
  • 스텝 커버리지 자동 측정(바닥÷상부), 사이드월 각도, 접합 깊이
  • 도핑 프로파일 그래프(농도 vs 깊이, 로그 스케일) — 결정 A의 이유
  • 단계 간 변경분 하이라이트 — 추가된 것/제거된 것

레슨과 주석

노드에 설명 텍스트를 붙일 수 있게 하고("왜 여기서 CMP를 하는가"), 예제 레시피는 단계마다 설명이 달린 채로 배포합니다. 가이드 레슨(정해진 순서로 따라가며 각 단계에서 관찰 과제를 주는 모드)은 그 위에 얹는 것이고, 범위 결정이 필요합니다.

내보내기

단면 PNG, 3D 스크린샷, 공정 전체 애니메이션 GIF/WebM, 단계별 요약 표. 보고서·발표 자료용이라 학생과 교사 모두에게 쓸모가 큽니다.

4 · UI 정보 구조

주 흐름

그래프 편집 → (자동 실행) → 관찰 → 수정. 네 가지 뷰의 관계가 정해져야 합니다.

  • 단면 뷰가 주인공입니다 — 교과서가 단면으로 가르치고, 학습은 여기서 일어납니다. 화면에서 가장 크고 항상 보입니다.
  • 3D 뷰는 공간 직관용 — 단면 옆에 작게, 필요하면 확대. 절단면 슬라이더, 재질별 표시/숨김(기존 Unity의 MaterialToggle을 계승).
  • 타임라인은 단면·3D 아래에 가로로 — 단계 스크럽이 두 뷰를 동시에 움직입니다.
  • 노드 그래프는 왼쪽 패널 또는 토글 — 노드를 선택하면 타임라인이 그 단계로 가고, 파라미터 패널이 열립니다.
  • 마스크 디자이너는 모달 또는 별도 탭.

이 배치는 제안이고, 와이어프레임 수준으로 한 번 그려서 확정하는 게 맞습니다.

마스크 디자이너

기존 Unity판의 브러시·격자 라벨·미니맵·저장/불러오기를 계승하되, 웹에서는 사각형·다각형·선 도구와 격자 스냅이 브러시보다 중요합니다(리소 패턴은 대부분 직선). PNG 가져오기, 반전, 배열 복제, 좌우 대칭 정도가 실용적입니다.

5 · 앱 상태와 저장소

  • 상태 분리 — 프로젝트 상태(그래프·자산·설정, 저장 대상) / 시뮬레이션 결과(스냅샷, 파생·재계산 가능) / UI 상태(선택·뷰 설정·카메라, 저장 안 함).
  • 편집 undo/redo는 그래프 편집에 대한 것이고, 타임라인 스크럽과는 별개입니다. 둘을 섞으면 혼란스럽습니다.
  • Worker 프로토콜 — 메인 → Worker: run(fromStep, toStep, project), cancel(jobId). Worker → 메인: progress(step, pct), stepDone(step, snapshotTransferable). 대용량 배열은 복사가 아니라 이전(transfer)합니다.
  • IndexedDB — 프로젝트(JSON), 마스크(Blob), 스냅샷 캐시(압축 배열, 프로젝트·단계·시뮬레이터 버전으로 키). 스냅샷은 캐시라 언제든 버려도 됩니다.
  • 결정성 — 같은 레시피는 어느 기계에서나 같은 결과를 내야 합니다. 난수 없음, 광선 방향 고정, union-find 동점 순서 고정. 레시피에 시뮬레이터 버전을 적고, 알고리즘이 바뀌면 버전을 올립니다.

6 · 메모리 예산과 기본 격자

600만 격자에서의 상주 메모리: 재질 6 + φ 24 + 도핑 72 = 102 MB. 스크래치(결정 S) ~100 MB, 스냅샷 캐시 20단계 × 1~5 MB, Three.js 표면 지오메트리 ~60 MB. 합계 300~400 MB. 데스크톱 브라우저는 괜찮지만, 교실 노트북이나 태블릿에서는 위험합니다.

제안: 기본 격자는 약 150만 복셀(예: 240 × 100 × 64), 600만은 "고해상도" 프리셋으로. 교육용 구조는 150만으로 충분히 표현되고, 단계당 시간도 4분의 1로 줄어 자동 재실행이 훨씬 편해집니다. 도핑 필드는 바운딩 박스로 국한하면 더 줄어듭니다.

7 · 테스트 전략

이미 강점이 하나 있습니다 — 검증된 Python 참조 구현이 있다는 것. 이걸 테스트 오라클로 씁니다.

  • 골든 테스트 — 적대적 시퀀스를 Python과 TypeScript에서 같은 격자로 돌려 재질 배열의 해시를 비교. 원시연산이 바뀔 때마다 자동 실행.
  • 원시연산 단위 테스트 — EDT는 브루트포스와 대조, FMM은 균일 속도에서 EDT와 대조, union-find는 flood-fill sweep과 대조(이미 스크립트 있음).
  • 연산자 회귀 — 검증 스크립트의 수치(커버리지 오차 0%, 핀치오프 지연 ≤14%, 어닐 σ 오차 0%)를 임계값으로 고정.
  • 결정성 테스트 — 같은 레시피 두 번 실행 → 동일 해시.

11 · 명시적으로 범위 밖

설계를 지키려면 하지 않을 것도 적어야 합니다.

  • 소자 시뮬레이션(I-V, 전기 특성) — 구조 예측까지가 목표
  • 실제 리소그래피 광학(aerial image, OPC) — 코너 라운딩 노브까지만
  • 응력·변형, 열 예산 추적 — LOCOS bird's beak는 이 때문에 보류
  • 결정 방향 의존 식각 — 훅만(결정 B)
  • 실시간 협업, 서버 저장 — 파일 기반 공유로 충분

12 · 교육 범위 결정 (확정)

  • 기본 격자 — 확정 약 150만(240 × 100 × 64) 기본, 600만은 고해상도 프리셋
  • 예제 레시피 범위 — 확정 단위공정 실습(트렌치 증착 · LOCOS · STI · 게이트 · 콘택/플러그) + 완성형 NMOS 하나. CMOS 인버터는 범위 밖
  • 사용자 정의 재질 — 확정 허용. 재질·공정 표는 편집 가능하고 프로젝트에 함께 저장
  • 가이드 레슨 — 확정 노드 주석까지. 관찰 과제가 있는 레슨 모드는 나중에

이로써 설계 단계의 열린 질문은 LOCOS bird's beak(응력 의존 산화, 보류) 하나만 남습니다. 다음은 M1c 구현입니다.

시뮬레이션 코어 설계는 연산자 명세에, 실행 가능한 코어는 M1 페이지에 있습니다. 이 문서는 그 바깥 — 프로젝트 전체 — 를 다룹니다.
