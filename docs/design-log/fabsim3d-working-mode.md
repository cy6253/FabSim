FabSim3D에서 사용자는 **코드를 직접 작성하지 않는다.** 프로젝트를 어떻게 진행할지 가이드하는 역할이고, 구현은 전부 Claude가 맡는다 (2026-09-04 명시).

**Why:** 사용자는 Python 경험만 있고 TypeScript는 미경험이다 — 그래서 "사용자가 유지보수하기 쉬운 코드"보다 **정확성과 설계 일관성**을 우선해야 한다. 다만 사용자가 설계 결정을 검토하고 판단해야 하므로, 왜 그렇게 했는지는 명확히 설명해야 한다.

**How to apply:** 구현 세부를 사용자에게 떠넘기지 않는다. 결정된 사항은 메모리에 남기고, 설계 명세 아티팩트를 계속 갱신한다.

**2026-09-04 갱신 — 자율성이 올라갔다.** 사용자가 "지금 뭐 하는지 follow up 안 하고 있다, 전적으로 너에게 의지하겠다"고 했다. 따라서 **기술적 하위 결정은 묻지 말고 직접 내리고 결과만 간략히 보고**한다. 여전히 사용자에게 물어야 하는 것은 제품 방향 수준의 갈림길뿐이다 — 교육 범위(MEMS를 다룰지 같은), 어떤 개념을 가르칠지, 스코프를 늘릴지 줄일지. 기술 선택(EDT냐 FMM이냐, 자료구조, 알고리즘)은 내가 정하고 근거만 남긴다.
