**핵심 교훈 — EDT 근사가 통하는 조건:** 표면점의 속도가 그 광선 전체에 유지될 때만이다. 증착의 스텝 커버리지는 만족하지만 식각의 선택비는 아니다(경로 중간에 재질이 바뀜). **새 연산자를 설계할 때 "속도가 경로를 따라 변하는가"를 먼저 묻는다.**

**2차 검토(2026-09-04)에서 드러난 구현-설계 불일치:** M1까지 φ는 검사용 재구축만 했고 연산자는 재질 ID를 정수 임계값으로 직접 썼다. 즉 "0.4×5=0" 양자화가 설계에서는 해결됐다고 했지만 구현에는 남아 있었다. 결정 O로 φ를 진리의 원천으로 바꿔 해결. **격자 정렬 동점 주의**: 거리가 정확히 정수인 셀은 부동소수점 누적 방향에 따라 임계값 판정이 뒤집힌다 — 반 복셀 관례로 회피.

**실측 성능 (2026-09-04, M1c 브라우저판, 사용자 하드웨어):** 150만 격자 **0.71s/단계**, 600만 **2.15s/단계**. 복셀 4배에 시간 3.03배로 **선형보다 낫다(~N^0.79)** — EDT만 O(N) 고정이고 FMM·가시성은 표면적/영향부피를 따르기 때문. 결론: ①**기본 격자 150만 결정 검증됨**, ②**Web Worker 분할은 불필요**(단일 스레드로 예산 안), 다만 UI 비차단용 Worker는 여전히 필요, ③**편집 루프를 성립시키는 건 속도가 아니라 지연 평가**(결정 Q) — 20노드 중 3번 편집 시 끝까지 = 150만에서 7초/600만에서 21초지만, 보는 단계까지만 계산하면 0.7~2.1초.

**반복된 실수 패턴 — 검증 실패의 절반은 코드가 아니라 단언이 틀린 것이었다.** 지금까지 다섯 번: 보이드 "얼어붙음"을 총량으로 검사(새 보이드 생성은 정상 물리), 도즈 보존을 한 컬럼으로 측정(측면 확산으로 빠져나감), 표면 근처 σ를 자유공간 공식과 비교(무유출 반사가 σ를 낮춤), CMP 테스트 구조에 오버행 아래 재질이 없었음, m1c 비교에서 기하가 서로 달랐음. **검증이 실패하면 구현을 고치기 전에 "이 단언이 맞는 물리인가"부터 물을 것.**

**union-find 봉인의 함정 2건 (M1c에서 발견, 둘 다 2D 테스트가 놓쳤음):**
1. **미연결 컴포넌트의 fallback은 INF가 아니라 0이다.** 역시간에서 "어느 임계값에서도 바깥과 안 이어짐" = **연산 시작 전부터 봉인됨**이므로 seal=0. INF로 두면 "봉인 안 됨"으로 읽혀 **이미 존재하던 보이드가 다음 컨포멀 증착에 채워진다.** 2D 테스트는 보이드가 증착 *도중에* 생겨 이 경로를 안 탔다.
2. **"얼어붙음" 단언을 총량으로 하면 안 된다.** 컨포멀 캡이 다른 구역을 새로 막는 건 정상 물리다(3D에서 519→882, bbox x14–42→14–48). 올바른 검사는 **셀 단위** — 기존 봉인 셀이 전부 여전히 비어 있고 여전히 봉인돼 있는가(519/519 생존, 0 채워짐).

**φ 기준 변경의 부수 효과:** 옛 구현은 거리를 *성장 전선*(고체에 인접한 빈 칸)에서 쟀고 φ는 *고체 표면*에서 잰다. 약 1복셀 차이라 φ 판이 조금 덜 자라고, 그래서 봉인되는 보이드가 더 크다(306 → 519). φ 쪽이 물리적으로 옳다 — 전선 셀은 거리 0이 아니라 1이어야 한다.

**FMM 비용 경계 실측 (m1a_core.py 스윕):** 식각 시간별 FMM 방문 비율 — t=5 → 9.1%, t=15 → 13.7%, t=25 → 27.8%, t=35 → 50.2%, t=45 → 88.7%. **통상 식각(격자의 10~25% 제거)에서는 9~28%만 방문해 EDT보다 싸지만, 극단적 식각에서는 EDT와 비슷해진다.** 돌파 재계산은 1.5~2.2배 오버헤드를 붙인다(t=25에서 제거 21k인데 방문 31.6k, 3라운드).

**FMM 비용 모델 정정:** "600만 복셀에 3~8초"는 틀렸다. FMM은 격자 전체가 아니라 **전선이 도달하는 부피**에만 비용이 든다. EDT는 무엇을 하든 전체 격자를 도는 고정 비용이므로, 얇은 막이나 좁은 식각에서는 FMM이 오히려 싸다. 분기점은 벤치마크로 실측 중: https://claude.ai/code/artifact/df485d03-dd24-4aff-a15f-a778a97e476f

**검증 방법이 바뀐 지점 (2026-09-05):** M2까지는 파이썬에 먼저 넣고 옮겼다. 그건 브라우저
JS를 로컬에서 못 돌리던 제약 때문이었고, 지금은 Node가 있어 **TS 코어 자체를 실측**하는
쪽이 더 직접적인 증거다(파이썬은 알고리즘이 같은지만 말해 주지 배포되는 코드가 맞는지는
말해 주지 못한다). 그래서 물리 검토 §1~§5는 TS에서 재고 골든 테스트에 회귀를 남긴 뒤,
프로토타입과 파이썬 오라클을 **같은 값으로 옮겼다** — 오라클을 뒤에 남기면 parity가 매번
실패해 신호가 죽고, 다음 사람이 틀린 참조를 읽는다.

**패리티가 덮는 범위 — 그리고 덮지 않는 곳 (2026-09-06):** 프로토타입과 파이썬 오라클이
아는 재질은 **여덟 가지**뿐이다(vacuum·Si·SiO2·Si3N4·PR·PR_exposed·Metal·MetalSi). 앱이
그 뒤에 더한 폴리실리콘·W·TiN·Ti·Co·Al·Cu·비정질 탄소·SiON과, 그 위에서만 일어나는
공정(살리사이드가 폴리와도 반응하는 것, 탄소 하드마스크, 슬릿용 `RIE_ON`)은 **패리티
밖이다.** 그러니 새 재질 경로를 고쳤을 때 parity가 통과하는 것은 "검증됐다"가 아니라
"여기는 안 본다"는 뜻이다 — 실제로 살리사이드의 폴리 반응을 고친 변경은 parity를 하나도
안 건드렸다. 그쪽은 골든·교육 테스트가 셀 수로 붙든다. **패리티가 지키는 것은 커널과
표준 연산자**다: EDT·FMM·가시성·연결성·ADI와 여덟 재질로 도는 표준·적대 시퀀스.
