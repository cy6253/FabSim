FabSim3D에서 사용자는 **설계에 시간을 더 많이 쏟기를** 원한다 (2026-09-04). "설계가 완벽해야 결과도 좋을 것 같다"는 것이 이유다.

**Why:** 구현을 빨리 시작해 나중에 갈아엎는 것보다, 설계 구멍을 먼저 메우는 쪽을 선호한다. 실제로 Fable 모델에 독립 검토를 시켜 설계 결함을 여러 개 찾아냈고 그 방식이 효과가 있었다.

**How to apply:** "일단 만들고 보자"로 밀지 않는다. 설계 주장에 근거가 없으면 **2D 파이썬 스크립트로 실제 검증**한다 — 이 프로젝트에서 이미 세 번 효과를 봤다(식각 비단조성, 증착 근사 오차, 서브스테핑 양자화 발견). 성능 주장은 추정하지 말고 브라우저 벤치마크로 실측한다. 다른 모델(Fable 등)에 독립 검토를 맡기는 것도 유효한 수단이니 필요할 때 제안한다.
