2026-09-04 확정. 설계 논의 ①~⑨가 모두 끝났고 구현 착수 가능한 상태다.

**⑥ 스냅샷 · 재실행** — 스텝마다 상태를 저장하고, 그래프를 고치면 **고친 지점부터 자동 재실행**한다(Run 버튼 없음). 슬라이더 드래그로 매 프레임 재실행되지 않도록 입력이 끝난 시점에만 실행(디바운스). 저장은 **메모리 캐시 + IndexedDB 백업** 양쪽 — 스크럽은 메모리에서 즉각, 영속성은 IndexedDB로. 스텝당 원본 ~100MB(재질ID 6 + 표면φ 24 + 도핑 3종 72)이지만 압축 후 1~5MB 예상: 재질ID는 RLE, φ는 narrow band만, 도핑은 바운딩 박스만.

**⑦ 분기 실행** — **분기 + 전환.** 실행 모델은 분기를 지원하되 보기는 한 번에 한 갈래("이 갈래 보기"). 공통 앞부분은 스냅샷을 공유하므로 추가 계산 비용이 거의 없다. 나란히 보기 뷰포트는 나중에 UI만 추가하면 되고 실행 모델은 안 바뀐다. 기존 `ProcessGraphRunner`의 "output 포트 따라 전부 DFS 실행"은 분기가 안 되므로 교체 대상.

**⑧ 마스크 시스템** — 정렬은 **마스크 좌하단 원점 고정 + dx/dy 오프셋**(정렬 마크 UI는 만들지 않음). 저장은 IndexedDB(⑥과 같은 저장소), 내보내기/가져오기는 PNG. 비평탄면 위 노광은 **그냥 수직 투영** — 단차 때문에 PR 두께가 불균일해 현상 결과가 달라지는 것 자체가 "왜 CMP가 필요한가"를 보여주는 교육 지점이라 별도 처리 불필요.

**⑨ UI** — 노드 에디터는 **React Flow**. 따라서 UI 층에 React를 도입한다. 시뮬레이션 코어는 프레임워크 무관한 순수 TypeScript로 유지하므로 영향 없다. 화면 요소: 3D 표면 메시 뷰, 실시간 단면 뷰, 타임라인 스크럽, 노드 에디터, 마스크 디자이너, 재질 범례, 도핑 프로파일 그래프, 변경분 하이라이트, 지점 프로브.

**2차 검토 추가 (결정 Q·T·U):** ⑥의 자동 재실행이 약속을 지키려면 시뮬레이션을 **Web Worker**에서 돌리고(UI 비차단), **현재 보는 단계까지만 계산**(지연 평가)하며, 편집 중 재편집 시 **진행 중 계산을 취소**해야 한다 — 노드당 1~2초면 앞쪽 노드 편집이 수십 초가 되기 때문. 마스크는 **출력 포트를 가진 자산 노드**이고 노광·주입 노드가 마스크 입력 포트를 받는다(한 마스크 재사용, 정렬 오차는 사용처별). 단위 계층: 복셀↔nm 외에 시간·온도, 종별 D₀·Eₐ, Deal-Grove B·B/A(T) 표가 있어야 온도 노브가 의미를 가진다. 스크래치 버퍼는 격자당 한 번 할당해 재사용(결정 S).
