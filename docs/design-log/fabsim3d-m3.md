M3는 코어 주변의 빈 층을 채우는 단계다. 1~4단계(빌드 골격 · 코어 이식 · 테스트 ·
재질/공정 데이터화)가 끝났고, 나머지(레시피 · 노드 에디터 · 화면 · Worker)가 남았다.

**전제가 바뀌었다 — 개발 PC에 Node가 생겼다.** 이전 PC에는 없었고, 그 제약이
M1·M2의 구조를 직접 결정했다([[fabsim3d-m1]]의 "이 환경에는 Node가 없다"). 현재
PC는 Node v24.12.0 + npm 11.7.0, Python 3.12.10이다. 그래서 아티팩트 우회를
더는 쓰지 않는다.

**착수 전에 실측한 것.** 파이썬 참조 구현 5종이 이 PC에서 전부 통과하고, 한 번도
실행된 적 없던 `m2-ops.html`의 JS 코어를 Node로 처음 돌렸다 — 0.92M에서 14/14,
1.54M에서 14/14 통과(각 3.07s, 4.32s). 즉 M3의 코어 이식은 재작성이 아니라 이식이다.
유일한 실패는 0.28M 격자의 9단계였고 원인은 코드가 아니라 **단언의 격자 의존성**이었다
(산화가 질화막 가장자리를 묻어 등방 식각이 못 닿는 건 옳은 물리다). 기준을
`n1*4 < n0` 에서 `n1 < n0*0.35` 로 고쳤다.

## 완료된 것

**`web/app/` — Vite + TypeScript + React + Vitest.** 코어는 `src/core/`에 한 벌만
있고 프레임워크가 섞이지 않는다. 빌드·타입체크·테스트 전부 통과.

**전역 상태를 `Sim` 컨텍스트로 옮겼다.** 프로토타입은 NX/NY/NZ와 스크래치 버퍼를
모듈 전역으로 들었다. 그 방식으로는 M3에 필요한 분기 실행(⑦), Worker(결정 Q),
결정성 테스트가 전부 불가능하다 — 같은 코드가 서로 다른 상태 두 벌을 동시에
다뤄야 하기 때문이다. 배열 타입(Float32 vs Float64)은 결과를 바꾸므로 원본 그대로 뒀다.

**테스트 4종 37건, 약 20초.** 프로젝트 검토가 미설계로 남겨뒀던 층이다.

| 테스트 | 지키는 것 |
|---|---|
| `parity` | 이식이 프로토타입과 **비트까지** 같은가. 재질·φ·도핑 해시를 단계마다, 두 격자에서, 표준·적대적 시퀀스 둘 다. EDT 호출 횟수까지 대조 |
| `primitives` | 원시연산이 **애초에** 맞는가. EDT↔브루트포스, FMM↔EDT(평면 소스), union-find 봉인↔훑기 |
| `golden` | 파이썬이 검증한 물리 주장을 TS가 재현하는가. Deal-Grove 54건은 상대오차 1e-12 이내, 나머지는 관계로 |
| `sequence` | 14단계 단언 전부 통과, 결정성, 지연 재거리화 유지 |

`parity`와 `primitives`의 역할이 다르다 — 프로토타입이 틀렸으면 parity는 통과하고
primitives가 깨진다.

**시퀀스를 데이터로 분리했다** (`sequences/opList.ts`). parity 테스트가 같은
연산 목록을 두 구현에 먹이려면 시퀀스가 한 곳에만 있어야 한다. 화면(`smoke.ts`)과
목록이 갈라지지 않도록 최종 상태 해시를 교차 검사한다. 이 목록은 M3 후반
레시피(프로젝트 JSON)의 축소판이기도 하다.

**골든 다리** `web/reference/golden_dump.py` → `golden.json`. 순수 수식과 물성
상수는 자릿수까지 비교할 수 있지만 격자 결과는 못 한다(파이썬 float64 대 JS
Float32). 그래서 파이썬이 확인한 **주장**을 적어 두고 TS가 자기 격자에서
재현하는지 본다 — 검사하는 것은 숫자가 아니라 관계다.

## 새로 특성화된 것

**FMM 오차는 소스 모양에 달렸다.** 24³ 격자 실측:

| 소스 | 최대 상대오차 | 평균 | 과소평가 |
|---|---|---|---|
| 평면 | **0%** | 0% | 없음 |
| 직선 | 12.3% | 5.3% | 없음 |
| 점 | 22.5% | 8.3% | 없음 |

실제 사용은 전부 면 소스(식각 전선·증착 표면)라 정확하다. 중요한 것은 **결코
과소평가하지 않는다**는 점이다 — 전선이 기하학적으로 가능한 것보다 일찍 도착하면
없는 재질까지 깎인다. 오목한 소스 모서리에서만 1/√2 만큼 작게 나오는데(두 직교
면이웃이 모두 소스일 때 t = 0.707), 이건 1차 상풍 차분의 알려진 성질이다.

## 반복된 실수 패턴 — 여섯 번째, 일곱 번째

[[fabsim3d-verification-log]]가 기록한 "검증 실패의 절반은 코드가 아니라 단언이
틀린 것"이 이번에도 두 번 나왔다:

1. **9단계 질화막 제거** — 작은 격자에서 30%가 남는 것을 실패로 봤으나 옳은 물리였다.
2. **질화막 마스크 골든 테스트** — 패드 산화막을 마스크 밑에 깔아 놓고 패드가
   *없는* 경우의 단언(10배 차이)을 걸었다. 파이썬 참조는 두 경우를 나눠 검증했고
   LOCOS 배치에서는 1.56배밖에 차이가 안 난다. 테스트를 둘로 쪼개고, LOCOS 쪽은
   비율이 아니라 **침투가 유한한가**를 보게 고쳤다.

**여전히 유효한 규칙: 검증이 실패하면 구현을 고치기 전에 "이 단언이 맞는 물리인가"부터 묻는다.**

## 4단계 — 재질·공정이 데이터가 됐다 (2026-09-05)

**진짜 작업은 JSON 파일 추가가 아니라 코어에 박힌 재질 판정을 걷어내는 것이었다.**
여덟 군데에 하드코딩이 있었다:

| 전 | 후 |
|---|---|
| `m === OX \|\| m === NIT` (확산 장벽) | `diffusionFactor[m]` |
| `mat[i] === SI` (산화 대상) | `oxidizesTo[m] >= 0` |
| `mat[j] === OX` (산화제 통과) | `oxidantPermeable[m]` |
| `m === EMPTY \|\| m === OX` (산화제 점유) | `carriesOxidant[m]` |
| `m === PR` / `m === EPR` (노광·현상) | `exposure[m]`, `exposedForm[m]`, `unexposedForm[m]` |
| `mat[i] === PR \|\| mat[i] === EPR` (제거) | `isResist[m]` |
| SI/MET/MSI (실리사이드) | 레시피 (semiconductor·metal·product) |
| `CONSUME`/`GROW` 상수 | 소비 재질의 `expansion` |

`src/core/data/materials.json`(재질 17종 + 도펀트 3종)과 `processes.json`(식각액 9,
증착 5, 슬러리 3, 산화 6, 실리사이드 3, 주입 4)이 유일한 출처이고, `library.ts`가
**숫자 재질 ID로 색인되는 배열**로 편다 — 핫루프에서 문자열·객체 조회를 하면 안
되기 때문이다. 표는 `Sim`에 실려 다니므로 연산자 시그니처가 안 바뀌었다.

**정밀도 함정:** 물성 상수를 Float32Array에 넣으면 D_BLOCK(0.004)과 DREL(0.6)이
반올림돼 프로토타입과의 비트 동일성이 깨진다. 격자 크기 배열이 아니라 재질 수만큼의
작은 표이므로 Float64Array로 뒀다.

**Unity 원본에서는 이름과 구조만 가져왔다.** `EtchantConfig`/`CmpRateConfig`의
선택비가 전부 1.0인 자리표시자여서 수치로 쓸 수 없었다. 값은 실제 공정의 대략적인
비율로 채웠고, 어차피 물리 상수가 아니라 거동을 재현하는 노브다.

**증거로 삼은 테스트** (`library.test.ts`, 13건): 폴리실리콘 산화가 연산자 수정 없이
동작하고, 사용자가 산화막의 장벽 계수를 1로 바꾸면 어닐이 실제로 도펀트를 통과시킨다
(막힘 <1 대 열림 >10배). 그리고 잘못된 데이터(0번이 vacuum이 아님, id 중복, 없는
재질 참조, 공정이 모르는 재질 지목)는 조용히 넘어가지 않고 거부된다.

`opAnneal`/`segregate`가 라이브러리의 종 개수로 순회하던 것을 **호출자가 준 필드
개수**로 바꿨다. 종을 하나만 쓰는 호출에서 깨졌다.

**parity 테스트가 전부 그대로 통과한다** — 데이터 기반으로 바꾸고도 프로토타입과
비트까지 같다. 이 리팩터링을 안심하고 할 수 있었던 이유가 그 테스트다.

테스트 5파일 50건.
